# Планирование спринтов — веб-приложение

Веб-приложение для планирования по двухнедельным спринтам: **добавление и редактирование** данных
(как в книге `Планирование_спринта_PRO.xlsx`) с автоматическим пересчётом метрик и диаграммами.

## Возможности

- **Редактируемые данные:** Бэклог, Команда, Релизы, Вехи, Технический долг, Риски, Баги, Параметры —
  добавление, изменение и удаление записей прямо в таблицах.
- **Автоматический пересчёт:** ёмкость и даты спринтов, план, velocity, % выполнения, загрузка,
  Time to Market, health-index, DRE, содержимое релизов, тренд техдолга, матрица рисков — обновляются
  при любом изменении.
- **Дашборд** с KPI (RAG-подсветка) и диаграммами (SVG, без внешних библиотек).
- **Автосохранение** в браузере (localStorage), **Импорт/Экспорт** данных в JSON, **Сброс** к исходным.
- **Приоритизация RICE:** отдельная вкладка с оценкой фич по методологии
  RICE = (Reach × Impact × Confidence) / Effort — авто-расчёт балла, ранга, приоритета и диаграммы.
- **Межстримовые зависимости:** вкладка «Зависимости» — задачи/истории/фичи, зависящие от других стримов
  (направление, статус с RAG, риск, сводка и графики); зависимости отмечены маркерами ◆ на диаграмме Ганта.
- **Многопользовательский режим** (опционально): общий сервер + БД, синхронизация правок между всеми
  пользователями, необязательная защита ключом команды. См. раздел ниже.
- Светлая/тёмная тема, адаптивный макет; без сервера работает офлайн (один файл `index.html`).

## Режимы работы

Одно и то же `index.html` работает в двух режимах — приложение само определяет, есть ли рядом сервер:

1. **Одиночный (без сервера).** Данные хранятся в браузере (localStorage), обмен — через Экспорт/Импорт JSON.
   Индикатор в шапке: «⚪ локально». Подходит для локального файла и GitHub Pages.
2. **Многопользовательский (общий сервер + БД).** Все пользователи видят и редактируют **одни и те же**
   данные: приложение тянет состояние с сервера, сохраняет изменения и опрашивает обновления каждые 5 с.
   Индикатор: «🟢 онлайн». Требуется хостинг с сервером (не GitHub Pages).

## Запуск — одиночный режим

- Локально: открыть `index.html` в браузере.
- Онлайн (GitHub Pages): Settings → Pages → Deploy from branch → `main` / root →
  `https://neoandrey1985.github.io/Planirovanie/`.

## Запуск — многопользовательский режим (сервер + БД)

Сервер (`server/server.js`) хранит общее состояние в SQLite и раздаёт то же приложение.
**Внешних зависимостей нет** (используется встроенный `node:sqlite`), нужен только **Node ≥ 22**.

Локально:

```bash
cd server
node server.js
# открыть http://localhost:3000
```

Переменные окружения:

| Переменная   | Назначение                                            | По умолчанию          |
|--------------|-------------------------------------------------------|-----------------------|
| `PORT`       | порт сервера                                          | `3000`                |
| `TEAM_TOKEN` | общий ключ команды (если задан — API требует его)     | пусто (доступ открыт) |
| `DB_PATH`    | путь к файлу БД (для сохранности — на постоянном томе) | `server/data.db`      |

Когда `TEAM_TOKEN` задан, при первом входе приложение спросит ключ (хранится в браузере).

### Деплой на хостинг

- **Render** — New → Blueprint → этот репозиторий (`render.yaml`). Задайте `TEAM_TOKEN` в Environment.
  Постоянный диск для БД на плане free недоступен — для сохранности данных возьмите платный instance
  либо хостинг с томом ниже.
- **Fly.io** (`fly.toml`, есть бесплатный том): `fly launch --no-deploy --copy-config` →
  `fly volumes create data --size 1` → `fly secrets set TEAM_TOKEN=…` → `fly deploy`.
- **Railway / любой Docker-хостинг** — используйте `Dockerfile`; смонтируйте том на `DB_PATH`
  и задайте `TEAM_TOKEN`.

Перенос данных из одиночного режима: Экспорт JSON → на сервере один раз загрузить его
(Импорт JSON внутри приложения при подключённом сервере запишет состояние в общую БД).

## Модель данных и расчёты

- Даты спринта: `старт + (n−1)·14` … `+11`; рабочие дни — `ЧИСТРАБДНИ` (будни минус праздники из «Календаря»).
- Ёмкость спринта = Σ по команде `(раб.дни − отсутствия) × доступность × Focus factor`.
- План спринта = Σ оценок задач этого спринта; velocity = Σ оценок задач со статусом «Готово» (для закрытых спринтов).
- Time to Market = дата релиза − дата взятия задачи в работу; цель — 15 дней.
- Health-index = среднее из (% выполнения, готовность DoD, качество по открытым багам).

Данные приложения не покидают браузер (хранятся локально). Для переноса используйте Экспорт/Импорт JSON.
